Tech Stack Scout — Components Map

AI-powered tech-stack intelligence for Nikhil's target-account watchlist · MESA C4, Problem Statement 5
Live app: https://tech-stack-scout-kappa.vercel.app  ·  Repo: https://github.com/hrishitavijaywargi/tech-stack-scout
Stack: Next.js (TypeScript, Tailwind, Recharts) on Vercel · Supabase Postgres · Gemini Flash via @google/genai · 7 live public data sources

The pipeline at a glance

1 · TRIGGER
When
  • Vercel Cron weekly, Mon 06:00 UTC
  • Vercel Cron daily stale sweep
  • Supabase pg_cron, 10 min
  • Add / CSV / Refresh now
2 · INPUT
What
  • companies watchlist row
  • GitHub, job boards
  • DNS, crt.sh
  • HN, blog RSS, web search
3 · CONTEXT
Knows
  • Product profile
  • Previous snapshot
  • Tech dictionary (~185)
  • First-observed dates
4 · PROCESSING
Deterministic
  • Detect & aggregate stack
  • Per-tech confidence
  • Activity & fit scores
  • Snapshot diff
5 · AI
Gemini Flash
  • 2-paragraph summary
  • Outreach line (<35 words)
  • 3 talking points
  • Grounded web research
6 · OUTPUT
Delivered
  • Snapshot + insight rows
  • Account cards & brief
  • What's changed
  • CSV export
Design rule: code decides the facts (which technologies, which scores, what changed); Gemini only writes prose from an ID'd evidence pack, and its answer is validated against that evidence before it is saved. Nothing is invented — missing data is shown as "Not publicly found".

Data flow

1 · Trigger

ComponentImplementationNotes
Weekly refreshVercel Cron 0 6 * * 1 → /api/cron/refresh?source=vercel-weeklyThe freshness guarantee: every active company is re-researched 7 days after its last snapshot.
Daily stale sweepVercel Cron 0 7 * * * → ?source=vercel-dailyDrains anything older than 7 days so the queue always empties.
Supabase schedulerpg_cron */10 * * * * → same endpoint (URL + secret in Vault)Picks up rows added directly in Supabase within 10 min; retries; chained batches.
ManualAdd company · Upload CSV · Refresh now · Research all · Refresh all staleSame queue and pipeline as scheduled runs. Idempotent: one active job per company.
SecurityAuthorization: Bearer CRON_SECRET, constant-time compareVercel Cron sends the header automatically.

2 · Input

SourceCollectorWhat it contributes
Watchlistcompanies tablename, domain (required); optional github_org, job board provider/slug, blog_rss_url, notes, is_active. Edited in the UI or Supabase — no code.
GitHubcollectors/github.tsGraphQL: ≤300 non-fork repos with languages in 3 calls; all-time vs recent (180 d) language mix. REST: 52-week commit stats (202 retry), contributors, releases, file trees (Docker, k8s, Helm, Terraform, CI, proto), manifests, workflow contents, Terraform providers, Serverless provider. Microservices heuristic.
Job boardscollectors/jobs.tsGreenhouse / Lever / Ashby public APIs; auto-discovered board saved back; engineering roles; per-technology posting counts; 5 most relevant roles; hiring trend.
DNScollectors/dns.tsGoogle DNS-over-HTTPS: CNAME/NS → hosting/CDN, MX → email provider, TXT → ~45 SaaS verification records, SPF includes.
Certificatescollectors/crtsh.tscrt.sh: unexpired subdomains, tooling flags (grafana, jenkins, argocd, k8s, jira…). 25 s timeout, one retry.
Hacker Newscollectors/hn.tsLast-12-month engineering stories on the company domain or naming it; top 5 by points.
Engineering blogcollectors/rss.tsSaved or auto-discovered RSS/Atom feed (saved back); 5 latest posts, technical flag.
Web researchcollectors/webResearch.tsGemini + Google Search grounding: talks, migrations, announcements; URLs taken from grounding metadata only. Weak, supplemental evidence.

4 · Processing (deterministic, in code)

StepModuleDetail
Queuelib/jobs/queue.tsAtomic claim (FOR UPDATE SKIP LOCKED), 4 concurrent, 240 s per job inside a 300 s function, exponential-backoff retries, rate-limit pause for the whole queue, refresh_runs bookkeeping.
Pipelinelib/research/pipeline.tsCollect (parallel) → store sources/findings → stack → scores → Gemini → snapshot + insight + diff. One pipeline for manual, bulk and scheduled runs.
Stack + confidencelib/research/analysis.tsOne entry per technology with IDs F1…; high = 2+ independent source families, medium = public code/config or 3+ postings, low = single weak signal.
Activity scorelib/scoring.tsLog-scaled: commits 90 d ×30, repos active 30 d ×15, 90 d ×10, contributors ×15, releases 90 d ×15, eng roles ×15.
Fit scorelib/scoring.tsTarget languages ×40 (share of recent code, full at 60%), target clouds ×30 (by confidence), target signals ×30 (full at 5). Breakdown shown in the UI.
Language mixcollectors/github.tsBy code bytes, each repo capped at 2× the median repo size so a vendored codebase can't dominate.
Change trackingdiffSnapshotsNewly observed (≠ newly adopted), not re-observed (≠ stopped using), new postings, hiring change, releases, new repos, language shifts, activity level.

5 · AI (constrained) — Gemini Flash only

JobHowGuardrails
Evidence packlib/ai/report.tsCompact ID'd facts (F tech, M activity, R releases, H/J hiring, D DNS, S subdomains, A articles, W web) + scores + product profile. Never raw API dumps.
Insight@google/genai, JSON responseSchemaTwo-paragraph summary, outreach line (<35 words) + rationale, 3 talking points with evidence IDs, observation/hypothesis statements.
ValidationZod + evidence checksCited IDs must exist; no technologies outside the evidence; no brackets/placeholders, banned phrases or "you have a problem" claims; the line must name a cited detail. Up to 3 attempts with corrective feedback.
Web researchgoogleSearch grounding toolFinding URLs come from groundingSupports → groundingChunks; ungrounded lines dropped.
Models & limitsGEMINI_MODEL / GEMINI_FALLBACK_MODELgemini-3.6-flash primary, gemini-3.8-flash fallback on 429/5xx; daily-quota errors pause the queue until reset.
No evidenceDeterministic briefGemini is not called; the brief says "insufficient public evidence" and lists next research steps.
